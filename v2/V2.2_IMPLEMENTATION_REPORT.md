## 1. Summary

V2.1 had a working core: a three-party teleportation QDS simulation, a blind detector, a single statistical test, a two-state quarantine, and Ed25519-signed audit records created on download. It also had gaps that the roadmap identified:
- honest runs locked the link;
- eavesdropping was often mislabelled;
- incidents were not signed when they happened;
- state was lost on restart;
- several published claims had no evidence behind them.

V2.2 closes those gaps:

- **Detection** gained a second statistical tier. It decides whether signature contradictions come from the channel or from the signer, and it says "undetermined" when the data cannot tell.
- **Response** is now driven by the strength of the evidence. There is a WATCH state, evidence accumulation across transmissions (Fisher's method), a probation period after reset, a sequential early abort, adaptive test allocation and a simulated router.
- **Audit** records are issued automatically, hash-chained, carry per-verifier digests and real bounds, and can be hybrid post-quantum signed (Ed25519 + ML-DSA-65).
- **Persistence**: link state, replay nonces and audit records now survive restarts (SQLite).
- **Evidence**: 149 tests (was 99), three seeded experiment scripts (was one), and CI covering all of them.
- **Claims**: a corrected innovations document replaces the unsupported ones.

**Verification state:** 149 tests pass and 1 is skipped. The skipped test is the ML-DSA test; it runs when `dilithium-py` is installed, and it passed locally with the provider. All dashboard JavaScript passes `node --check`. The Qiskit backend was smoke-tested. **The dashboards have not yet been click-tested in a browser.**

V2.2 abstains instead of guessing, and still rejects every one of those transmissions.

## 3. Problems solved

Each entry gives the problem, its cause, the fix, and the evidence.

### P1. Honest noise locked the link
- **Problem:** At L = 16, 3.5% of honest transmissions were rejected. Each one was labelled `REPUDIATION_ATTEMPT` and immediately quarantined the link, so an honest signer was locked out.
- **Cause:** One rule mapped "binding OK, elimination failed" to repudiation, and every repudiation quarantined.
- **Fix:** The transmission verdict and the link response are separate. A new response policy (`policy.py`) quarantines immediately only when the evidence p-value is ≤ 10⁻³. Weaker evidence moves the link to **WATCH**. Tier 2 labels most small-L honest failures `UNDETERMINED_DISTURBANCE`.
- **Evidence:** 0/200 honest runs quarantined at every L. `test_weak_small_l_noise_does_not_lock_the_link`.

### P2. The first WATCH policy still locked honest sequences too often
- **Problem:** A plain "two weak alerts → quarantine" rule locked 12% of honest 10-run sequences at L = 16. This was found by the new lock-out experiment.
- **Fix:** Escalation now combines the p-values of alerts within the window using **Fisher's method**. It quarantines when the combined p ≤ 0.01, or after three alerts.
- **Evidence:** 4.0% [2.0, 7.7] at L = 16; 0% at L = 32 and 64. `test_fisher_combination_values`, `test_borderline_alerts_do_not_escalate_but_moderate_ones_do`.

### P3. Eavesdropping at small L was mislabelled as repudiation
- **Problem:** With 16 test tokens, Tier 1 misses about 20% of full intercepts. The elimination check still caught them, but they were labelled `REPUDIATION_ATTEMPT` (22.5% of intercept runs).
- **Fix:** A new **Tier 2** (`discriminator.py`) asks whether the contradictions are explained by the measured channel disturbance. If the test-token error rate is elevated and the contradictions are in proportion, the run is attributed to the channel.
- **Evidence:** correct labelling at L = 16 rose from 77.5% to 91%. `test_tier2_attributes_proportional_disturbance_to_the_channel`.

### P4. The detector guessed causes it could not know
- **Problem:** Any unexplained contradiction became "repudiation", even when an honest fluctuation, a weak attack or a dishonest signer were all consistent with the data.
- **Fix:** Added the `UNDETERMINED_DISTURBANCE` classification. The run is still rejected and the cause is reported as not attributable. The experiments report it separately as an abstention rate.
- **Evidence:** `sweep_tiers.md` shows the trade-off in both directions.

### P5. "Tier 2" existed only as a name
- **Problem:** The second tier was the same elimination threshold presented as a separate tier. KL divergence was not implemented.
- **Fix:** Tier 2 is now a distinct, parameter-free conditional test. Given D total disturbance events, the contradiction count is Binomial(D, π), with π = (n/2)/(t + n/2), whatever the channel error rate is. KL divergence from the honest reference is shown as a diagnostic, with Jeffreys smoothing, and is explicitly not used as a detector.
- **Evidence:** `test_tier2_*`.

### P6. Tier 1 did not show its own numbers
- **Fix:** The channel test now reports `k/n`, the planned count, the exact p-value, the exact false-alarm level, and the Chernoff–KL bound `exp(−n·D((k+1)/n ‖ p₀))` beside it. That bound replaces the ad-hoc Poisson formula from the original claims.
- **Evidence:** `test_chernoff_kl_bound_dominates_exact_tail`.

### P7. Attacks were detected only after the whole stream was sent
- **Problem:** Detection ran after the full transmission (about 300 ms on Qiskit), so the claimed "trip during transmission" was not real.
- **Fix:** **Sequential early abort.** Test tokens are interleaved at secret random positions, and the stream is sent in four blocks. After each block the running error count is checked. Once it exceeds the quarantine-grade threshold the rest of the stream is never sent. Errors only accumulate, so stopping early does not change the false-alarm level. The p-value is computed conservatively over the planned count.
- **Evidence:** intercepted streams stop after 54–67% of tokens on average. On Qiskit, observation time falls from about 320 ms to about 160 ms. `test_full_intercept_aborts_early_and_is_not_revealed`.

### P8. Aborted sessions were still revealed
- **Problem:** After a channel alarm, Alice still revealed her signature to the verifiers.
- **Fix:** An aborted session is never revealed; the transcript records that nothing was delivered. The verifier dashboards show "SESSION ABORTED AT DISTRIBUTION".

### P9. Timing claims mixed different intervals
- **Problem:** One "30–80 µs reaction time" figure was quoted against a "< 2 ms during transmission" claim.
- **Fix:** Seven intervals are measured separately and reported with p50/p95/p99 at `/api/metrics`: channel observation, detection, post-verdict enforcement, incident signing, audit signing, HTTP-423 refusal, and the whole run.

### P10. Incident certificates were not issued at incident time
- **Fix:** Entering QUARANTINED allocates an incident id. The engine signs a `kind: incident` record at that moment, and it is linked from the transaction record, the banner and the admin incident list.
- **Evidence:** `test_incident_is_signed_at_quarantine_time`; the API test fetches and verifies it.

### P11. Audit records were created on download, and could differ between downloads
- **Fix:** Every transmission gets exactly one record at assessment time. The exact signed bytes are persisted, and downloads return the stored record without re-signing.
- **Evidence:** `test_audit_is_issued_automatically_and_verifies` checks the download is byte-stable.

### P12. Audit records lacked the promised contents
- **Fix:** Records are now `hedwig-audit/2` and add:
  - SHA3-256 digests of each verifier's elimination table;
  - a SHA3-256 digest of the keep/forward (symmetrisation) actions;
  - a channel-test digest;
  - the per-verifier bounds with inputs, formulas and assumptions;
  - Tier 2 statistics;
  - a model-based fidelity estimate, or "not reported";
  - a computed assurance level, expiry time, response and incident id, and disclaimers.

  The evidence is attached to the record and bound by the digests, so the offline verifier can recompute them.
- **Evidence:** `test_audit_record_verifies`, `test_evidence_tampering_is_detected`.

### P13. A deleted audit record could not be noticed
- **Fix:** All artifacts form one append-only hash chain: each record carries the SHA-256 of the previous signed payload and a sequence number. `verify_chain` reports broken links and sequence gaps.
- **Evidence:** `test_every_transaction_gets_one_chained_record` (removing one record breaks the chain).

### P14. No post-quantum signature, and no path to one
- **Fix:** Added pluggable signers (`signers.py`). When `dilithium-py` or `liboqs-python` is installed, records are **hybrid** signed with Ed25519 and ML-DSA-65, and verify only if both signatures do. The signature suite is inside the signed payload, so stripping the ML-DSA signature is detected. Ed25519-only records never claim to be post-quantum.
- **Evidence:** `test_hybrid_post_quantum_signature` (verified locally with `dilithium-py` 1.4.0, and in CI); `test_ed25519_only_record_is_never_reported_post_quantum`.

### P15. Key changes would invalidate old records
- **Fix:** `POST /api/audit/rotate-key` retires the active key into a keyring, and retired keys still verify old records.
- **Evidence:** `test_old_records_verify_after_key_rotation`.

### P16. State was lost on restart
- **Problem:** A quarantined link came back open after a restart, and consumed nonces were forgotten, so an old package could be replayed.
- **Fix:** A SQLite store (`store.py`, `data/hedwig.db`) holds link states, the transition log, consumed nonces and every signed artifact. Nonce consumption is an atomic insert, so two concurrent identical packages cannot both be accepted.
- **Evidence:** `test_link_state_survives_restart`, `test_replay_nonce_survives_restart`, and `test_state_and_records_survive_restart` (the server module is reloaded against the same database).

### P17. Reset needed no justification and left no trace
- **Fix:** A reset needs the admin role **and** a reason of at least 3 characters. It issues a signed `link_reset` record and moves the link to **probation** (RESET_PENDING) rather than straight to OPEN. One clean transmission reopens the link; any quantum-evidence alert re-quarantines it.
- **Evidence:** `test_reset_requires_admin_and_reason`, `test_probation_failure_requarantines`.

### P18. An outsider could lock the honest signer out
- **Problem:** Any rejection could trigger enforcement.
- **Fix:** Classical rejections (replay, impersonation, message integrity) never change link state, because anyone can produce them at will. Only quantum evidence can.
- **Evidence:** `test_non_qualifying_rejection_leaves_link_open`; the replay API test asserts `response_action == "none"`.

### P19. The message binding was loosely specified
- **Fix:**
  - Documented canonical encoding (`canonical.py`: sorted keys, UTF-8, no Unicode normalisation, NaN rejected).
  - A domain-separated message digest.
  - SHA3-512 is selectable, and the algorithm name is inside the commitment, so it cannot be downgraded.
  - Malformed blinding values are rejected instead of raising an error.
- **Evidence:** `test_any_context_change_is_rejected_without_labels` (6 fields), `test_signature_cannot_be_transplanted_to_another_session`, `test_sha3_512_digest_option`, `test_message_digest_is_domain_separated_and_not_normalised`, `test_commitment_rejects_malformed_blinding`.

### P20. The "hash-driven basis schedule" idea had never been tested
- **Fix:** Implemented three schedules (random, public hash, keyed HMAC) and a schedule-aware eavesdropper, and compared them at equal qubit budgets.
- **Result:** a public schedule lets Eve learn the verifiers' eliminated states. At a full tap, the forgery's contradiction rate falls from 0.23 to 0.005, and the quantum check alone would accept 83% of the forgeries that got past the channel test. The keyed schedule matches random. **Random bases remain the default.**
- **Evidence:** `experiments/basis_schedule.md`, `test_eve_measuring_in_the_verifier_basis_learns_the_outcome`.

### P21. There was no channel router
- **Fix:** Added a simulated router (`router.py`) with per-hop state (up / degraded / probation / down), token counters and drop counts. A quarantined hop refuses routing before any token is prepared. It is drawn on the admin page.
- **Evidence:** `test_router_drops_quarantined_link`, `test_router_counts_tokens`.

### P22. Published claims outran the evidence
- **Fix:** `../INNOVATIONS_TEAM_ATHENA_V2.2.md` replaces the unsupported claims with implemented behaviour and measured numbers, including a table of what was removed and why (§10).

## 4. New features

### 4.1 Detection
| Feature | Where | What it does |
| :--- | :--- | :--- |
| Tier 2 disturbance attribution | `src/quantum_engine/discriminator.py` | Conditional binomial test for excess contradictions, plus a channel-elevation test. Returns channel, signature or undetermined. |

| `UNDETERMINED_DISTURBANCE` | `detection.py` | Rejects without asserting a cause |

### 4.2 Response (Quantum Circuit Breaker)
| Feature | Where | What it does |
| :--- | :--- | :--- |
| Response policy `hedwig-qcb/2` | `policy.py` | Verdict and response kept separate; strong/weak/classical severity |
| Four-state breaker | `enforcement.py` | OPEN → WATCH → QUARANTINED → RESET_PENDING → OPEN, with atomic, logged transitions |
| Fisher evidence accumulation | `policy.py`, `enforcement.py` | Combines weak alerts inside the 15-minute window |
| Watch expiry | `enforcement.py` | WATCH returns to OPEN when the window passes with no new alert |
| Probation after reset | `enforcement.py` | One clean run reopens the link; any quantum-evidence alert re-quarantines it |
| Sequential early abort | `protocol.py`, `channel.py` | Stops the stream once the error count is decisive |
| Adaptive test allocation | `protocol.py` | Twice as many test tokens on WATCH or probation |
| Simulated router | `router.py` | Per-hop state, counters and drops |
| Separated timing | `enforcement.py` (`LatencyStats`) | 7 named intervals with p50/p95/p99 |
| Immediate incident records | `protocol.py`, `audit.py` | Signed at quarantine time |

### 4.3 Audit

## 10. Claims corrected

| Original claim | Status now |
| :--- | :--- |
| Message "physically entangled"; ~50% contradictions on tampering | Removed: tampering is caught by the commitment with zero quantum contradictions |
| Information-theoretic tamper-proofing | Removed: the binding is computational |
| QCB < 2 ms during transmission; Bell pairs destroyed | Replaced with separately measured intervals, early abort, and "software records purged" |

| Hash-driven basis schedule adds security | Tested: a public schedule harms security, a keyed one adds nothing measurable. Not adopted. |
| 100% deterministic physics | Replaced with "fixed, prespecified statistical rules; outcomes are probabilistic" |

## 11. Decisions taken

| Question | Decision | Reason |
| :--- | :--- | :--- |
| Post-quantum signing | Optional hybrid: Ed25519 always, ML-DSA-65 when installed | No new hard dependency and no demo risk on Windows; genuine PQ protection when enabled |
| Persistence | SQLite in `data/hedwig.db` | Standard library, atomic writes, survives restarts |
| Breaker model | OPEN → WATCH → QUARANTINED → RESET_PENDING | Directly addresses false lock-outs; gives an evidence trail |
| Escalation rule | Fisher-combined p ≤ 0.01 or 3 alerts | The measured two-strike rule locked 12% of honest sequences |
| Basis schedule | Random bases stay the default | The experiment showed no gain from keyed and harm from public |
| Original innovations document | Kept unchanged; corrected version added | Preserves history; slides should use the corrected file |

## 12. Known limitations and remaining work

**Limitations**
- It is a simulation: no photonic hardware, no physical qubits.
- Tier 2 assumes independent, Pauli-type errors. With bursty noise it still gives a confident wrong cause for 4.5–10% of honest runs, and at L = 16 it abstains on most dishonest-signer runs.
- The bounds are illustrative Hoeffding and binomial bounds, not a composable proof. They do not cover coherent attacks.
- Distribution records and in-flight sessions are not persisted; they must be re-sent after a restart.
- `dilithium-py` is a pure-Python reference implementation that is not side-channel hardened. Use `liboqs-python` beyond a demonstration.
- The detector is slower than in V2.1 (≈ 60–380 µs vs ≈ 30 µs).
